# 草稿暂存区说明

这个文件夹是"随时随地写故事文本 → 回电脑后一句话叫我配置进引擎"的中转站。你不用管 JSON 格式，正常写中文叙述就行。

## 手机端怎么用

用 GitHub App 打开 `RoadTripHTMLGame` 仓库，找到本文件夹下对应的文件，点右上角编辑，写完直接 commit 到 `master`。commit message 随便写，不影响处理。

## 标记约定

每个草稿文件内部分两块：

- **顶部**：新写的内容，用 `## [PENDING]` 开头另起一段，不用写日期。一次 commit 可以写多段，也可以只写一段。
- **文件末尾「已归档」区**：我处理完之后，会把对应段落的标题改成 `## [DONE] YYYY-MM-DD`（日期是我处理这段的当天日期，不是你写的日期），并挪到这里，正文原文保留（不删），方便你回看哪些已经进了正式内容、原话是什么。

回电脑后你只需要说"看一下草稿"或者指定"看一下 day2 草稿"，我会自己 `git pull` 拉取你手机上的 commit，然后读文件、处理 `[PENDING]` 段落。

## 五个文件分别放什么

| 文件 | 放什么 | 最终会配置进 |
|---|---|---|
| `day1.md` / `day2.md` / `day3.md` | 当天具体发生的事、地点描述、对白、事件文本 | `content/days.json` 对应天数的 `events` |
| `outline.md` | 跨天的主线走向、伏笔呼应、结局方向、真相设定这类不属于单一天的整体设定 | `design-doc.md` + 跨天 mainline 事件安排 |
| `items.md` | 新的线索/调查素材点子——是什么、在哪找到的、大概多重要 | `content/materials.json`（对应事件里的 `clue` 字段） |

写的时候不用纠结该放哪个文件，写错了我处理的时候会挪过去，不影响。

## QQ/BB 对某个事件的反应对话（气泡弹窗）

如果想让某个事件发生后，弹出一段 QQ 和 BB 两人对这件事的讨论（左右气泡逐条弹出，见 `engine/dialogue.js`），写法：紧跟在那段事件描述后面，直接写对话，一行一句，前面标好是谁说的：

```
QQ：这传单也太旧了吧。
BB：旧是旧，但你看日期——上个月才贴的。
```

不用管这段最后配置进 `events` 数组还是单独进 `dialogues` 数组——正常写“事件描述 + 后面跟一段 QQ/BB 对话”就行，我处理的时候会自动识别哪段是事件正文、哪段是反应对话，配进 `content/days.json` 对应事件的 `dialogues[].lines`。不是每个事件都需要配对话，觉得没必要吐槽的事件不写就行。

## 一个事件太长，想分成好几屏

事件文本会整段弹在一个窗口里，太长的话读起来很挤。如果想让某个事件分成好几屏——玩家每点一次"继续"翻一屏，而不是一次性看完——写草稿的时候就在想分屏的地方换行，正常写就行，不用加任何特殊标记：

```
旅馆里没有工作人员，大堂却干净整洁。桌上贴着自助入住的说明……

QQ 看中了 108 号房，两人凑够了现金办完入住。
```

我处理的时候会照你换行的地方拆成对应的屏（配进 `events[].text` 里的字面换行符）。QQ/BB 的反应对话也可以插在任意一屏后面，不一定非要在事件的最后——写在哪一段描述后面，就代表那一屏播完对话才能翻下一屏。
